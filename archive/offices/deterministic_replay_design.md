# Deterministic replay for debugging — design note (no code yet)

Agreed design from the Mani/Claude discussion. Debugging a sense-and-respond
office by replaying a bounded episode deterministically and inspecting it per agent.

## 1. NOW = a global snapshot; an episode is between two consistent cuts

- "Replay to NOW" is ill-defined without clocks. Instead NOW is *defined* by
  initiating a fresh Chandy-Lamport snapshot. The debugging window is the interval
  between snapshot **N** (start) and snapshot **N+k** (= NOW).
- The episode is therefore **bounded** and the replay **terminates** at cut N+k — a
  repeatable unit of debugging, not a chase of a moving stream.
- **Self-check (correctness oracle):** replaying forward from snapshot N must
  reproduce *exactly* snapshot N+k. If the end-state differs, the logging is
  incomplete. The two-cut framing validates itself.

## 2. Replay runs separately from the live system

- Sense-and-respond systems should not be stopped to debug. The live office keeps
  running; replay is a **separate process/replica** reconstructed from: snapshot N
  (start state) + source input logs for [N, N+k] + merge-order logs for [N, N+k]
  (+ nondeterministic-worker output logs, if any).
- Properties this buys:
  - **Perturbation-free**: heavy instrumentation on the replica never touches
    production (no probe effect on the live system).
  - **Re-runnable**: logs are immutable, so the episode can be replayed repeatedly.
  - **Faster than real time**: replay never waits for real inputs.

## 3. What is logged (minimal set)

- **Ordering nondeterminism** -> each async (fair) merge records its inport-choice
  **order** for the interval. Order only, not content, when workers are
  deterministic.
- **Content nondeterminism** -> each nondeterministic worker (LLM, random,
  time-of-day) logs its **outputs** (inputs are reconstructed by replay). Empty set
  when all workers are deterministic (the trading-desk demo).
- **Deterministic workers log nothing** — their tapes are regenerated by
  re-execution during replay, for free.
- Minimal log = {merge orders} ∪ {nondeterministic-worker outputs}.

## 4. What Pat sees: per-agent tapes (the payoff)

- The replay produces a dict: **agent -> sequence of (inputs, outputs)** — each
  agent gets its own sequential tape.
- **Reduction:** deterministic replay + per-agent projection turns "debug a
  concurrent distributed office" into "debug a few independent sequential programs,"
  one per worker. Matches the assumption that bugs are localized to one/few agents,
  and matches how Pat thinks (one worker at a time; never the global interleaving).
- **Optional escalation:** when a bug is in the *interaction* rather than one agent,
  tag messages with provenance (producer agent + sequence number) so Pat can follow
  a single message from producer to consumer. Base case per-agent; escalation is
  message-threading.

## 5. Retention (bounded logs)

- Keep logs only back to the last checkpoint (or last two for safety); discard
  older. Symmetric with the existing source-log retention. Bounds log size and
  bounds the replay window to recent behavior.

## 6. Relation to existing machinery

- The merge log reuses the **source boundary protocol** by symmetry: append-only
  log + `ptr(N)` at the checkpoint + playback of `log[ptr(N)+1 ..]` on resume, with
  a fair merge treated as an internal source of nondeterminism.
- **Anchoring condition:** set the merge's replay-log pointer at the marker-forward
  instant (agent-algorithm step 3), so downstream channel-state (messages in flight
  *before* the marker) and the merge log (messages *after* the marker) partition the
  post-cut stream with no gap and no overlap.

## One-line contribution

Minimal message logging between two consistent cuts reduces distributed debugging
of an office to per-agent sequential inspection, with a replay that checks itself
against the next snapshot.
